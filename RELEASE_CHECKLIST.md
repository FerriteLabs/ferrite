# Ferrite Release Checklist

> Set `VERSION` to the release being prepared. The current target is `0.5.0`.

## Pre-Release

- [ ] Set the shell variable used by the commands below: `export VERSION=0.5.0`
- [ ] All CI checks pass: `cargo fmt --all --check && cargo clippy --workspace -- -D warnings`
- [ ] All unit tests pass: `cargo test --workspace --lib` (every reported suite must finish with `0 failed`; the test count is expected to grow)
- [ ] Integration tests pass: `cargo test --test integration_harness`
- [ ] No `cargo-deny` advisories: `cargo deny check`
- [ ] No `cargo-audit` vulnerabilities: `cargo audit`
- [ ] CHANGELOG.md `[Unreleased]` entries moved to `[VERSION]` with the release date and comparison links updated
- [ ] Workspace and internal dependency metadata use VERSION: `cargo metadata --locked --no-deps --format-version 1`
- [ ] `Cargo.lock` was regenerated by Cargo and all workspace package entries use VERSION
- [ ] The remote tag is unused: `! git ls-remote --exit-code --tags origin "refs/tags/v${VERSION}" >/dev/null 2>&1`
- [ ] The crates.io metadata/package preflight succeeds without secrets: `gh workflow run publish.yml --ref <release-commit> -f dry_run=true -f expected_version="${VERSION}"`
- [ ] The completed `Publish to crates.io` run shows a successful **Preflight** job; a missing or skipped preflight is a release blocker
- [ ] Confirm the preflight reports `ferrite-forge` and `ferrite-spike-bridge` as staged dependents: their metadata/tests run before tagging, and their full `cargo publish --dry-run` runs in the protected publish job only after VERSION dependencies reach crates.io
- [ ] Ownership is confirmed for every already-published crate: `cargo owner --list <crate>` includes the release operator or approved FerriteLabs team
- [ ] Resolve the confirmed `ferrite-core` namespace collision: crates.io currently attributes it to `master-of-zen/ferrite`; obtain a verified transfer and set the exact transferred crates.io login in the `CRATES_IO_TRUSTED_OWNER` repository variable, or approve a separately reviewed rename before tagging
- [ ] First-time crate names and ownership/token access are confirmed before tagging; do not weaken or bypass a failed dry-run
- [ ] Verified domain blocker (2026-09-02): `ferrite.dev` has no DNS and `ferrite.rs` serves a parked email-hosting page; no release-facing documentation, startup/configuration help, support guidance, take-home material, examples, marketplace defaults, or command errors may advertise them as live endpoints, and the GitHub fallbacks must remain in place
- [ ] Verified contact blocker (2026-09-02): `ferritelabs.dev` does not resolve; current public conduct guidance and SDK package metadata must not publish `security@ferritelabs.dev`, `hello@ferritelabs.dev`, or `docs.ferritelabs.dev`, and SDK author fields must retain only the organization name until a verified contact domain exists
- [ ] Restoring branded-domain URLs or email requires verified FerriteLabs ownership, working DNS, valid HTTPS, deployed content or mail routing, and an explicit link check; do not invent or publish an unverified contact address
- [ ] README quick-start instructions verified on fresh machine
- [ ] License headers present in all source files
- [ ] `ferrite-ops/Dockerfile` ARG `FERRITE_VERSION` matches VERSION (checked in the sibling operations repository)

## Build Artifacts

- [ ] Linux x86_64 binary: `cargo build --release --target x86_64-unknown-linux-gnu`
- [ ] Linux aarch64 binary: `cross build --release --target aarch64-unknown-linux-gnu`
- [ ] macOS x86_64 binary: `cargo build --release --target x86_64-apple-darwin`
- [ ] macOS aarch64 binary: `cargo build --release --target aarch64-apple-darwin`
- [ ] Docker image: `docker build -t ferritelabs/ferrite:VERSION -f ../ferrite-ops/Dockerfile .`
- [ ] Docker multi-arch: `docker buildx build --platform linux/amd64,linux/arm64`
- [ ] SHA-256 checksums generated for all binaries

## Publish

- [ ] `git tag "v${VERSION}" && git push origin "v${VERSION}"`
- [ ] GitHub Release created with binaries + checksums + changelog
- [ ] The canonical `.github/workflows/release.yml` is the only tag-release pipeline; the removed legacy `release-full.yml` must not return
- [ ] Docker Hub: `docker push ferritelabs/ferrite:VERSION && docker push ferritelabs/ferrite:latest`
- [ ] crates.io publication is started explicitly after the tag release succeeds: `gh workflow run publish.yml --ref "v${VERSION}" -f dry_run=false -f expected_version="${VERSION}"`
- [ ] The protected `release` environment approval is completed and every requested crate is visible at VERSION before publishing the next dependent crate
- [ ] Homebrew formula updated: `homebrew-tap/ferrite.rb` → version VERSION

## Post-Release

- [ ] If the top-level `ferrite` package was published, verify `cargo install ferrite --version VERSION` works
- [ ] Verify `docker run ferritelabs/ferrite` works
- [ ] Verify `brew install ferritelabs/tap/ferrite` works
- [ ] Announce on GitHub Discussions
- [ ] Post to r/rust, r/redis, Hacker News
- [ ] Update ferrite-docs website with release notes
- [ ] Bump workspace version to NEXT_VERSION-dev

The top-level `ferrite` package is also excluded from the automated crates.io workflow while it has optional dependencies on those non-publishable packages. Resolve that packaging strategy before adding any excluded package to the publication workflow.
